## Constitution is Stacktic-generated

This project's constitution (`.specify/memory/constitution.md`) is **generated from the
stack** (components, links, attributes in `stack-metadata.yaml`) — it is the compiled
truth of this service's wiring and platform rules, not a hand-written document.

**Do NOT rewrite it here.** To amend it:

1. **Wiring/infrastructure principles change** → change the STACK (draw/remove links,
   set attributes) via the Stacktic MCP `design` tool or the platform UI, then rebuild.
   The stack repo regenerates `dev_tools/spec-kit/constitution.md`.
2. **Refresh this repo's copy** → re-run
   `<stack-repo>/external_source_code/<component>/dev_tools/spec-kit/install.sh <this-repo>`.
3. **Team-specific, non-platform principles** (code style, review rules) → add them to a
   SEPARATE section at the END of the constitution under `## Team Addenda` — the installer
   preserves nothing above it, so keep platform truth and team rules separate. Never modify
   Principles I–V.

Tell the user this, then show them the current constitution and where each part came from.
